What is MCP?

Model Context Protocol (MCP) is an open standard, introduced by Anthropic in November 2024, that defines how AI applications connect to outside tools and data. Think of it like USB-C: one plug shape, and any device works with any port.

Before MCP

Every AI app needed a custom connector for every service. 5 apps × 8 services meant 40 integrations to build and maintain.

With MCP

Each app speaks MCP once, each service exposes MCP once. 5 + 8 = 13 pieces, and everything works together.

Try it: the N×M problem

AI apps: 4 Services: 6
Custom integrations (N×M)With MCP (N+M)

Why it matters

Language models only know their training data. To check your calendar, query a database or open a pull request they need tools. MCP gives them those tools safely, with a consistent way to discover what is available.

Architecture

MCP has three roles. The host is the AI app you use (Claude Desktop, an IDE). Inside it, one client per connection keeps a 1-to-1 link with a server, a small program that exposes capabilities.

Messages

MCP uses JSON-RPC 2.0: requests with an id, responses, and one-way notifications.

Transports

stdio runs the server as a local child process. Streamable HTTP talks to a remote server over the web.

API vs MCP

MCP does not replace APIs. Most MCP servers wrap an API and make it easy for an AI to discover and use.

See the difference

Blue dots are requests, green dots are responses.

Side by side

Traditional APIMCP
Built forDevelopers writing codeAI models and agents
DiscoveryRead docs by handRuntime tools/list, self-describing
IntegrationCustom per serviceOne standard for all
ConnectionStateless requestsStateful session, with notifications
ChangesUpdate client codeClient re-lists capabilities
Best whenFixed app logicAn AI chooses actions on the fly

Also compare

MCP vs function calling
Function calling is how a model asks for a tool. MCP is how tools are packaged and shared across apps.
MCP vs plugins
Plugins were tied to one vendor. MCP servers work across many hosts.
MCP vs RAG
RAG retrieves text for context. MCP can also take actions, like creating a ticket.

Build your first server

Install the SDK with pip install "mcp[cli]", then save this as server.py:

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers"""   # the docstring is the tool description
    return a + b

@mcp.resource("greeting://{name}")
def greet(name: str) -> str:
    return f"Hello, {name}!"

@mcp.prompt()
def review(code: str) -> str:
    return f"Please review this code:\n{code}"

if __name__ == "__main__":
    mcp.run()   # stdio transport

Test it with mcp dev server.py (opens the Inspector). To use it in Claude Desktop, add it to the config file:

{ "mcpServers": { "demo": { "command": "python", "args": ["/path/to/server.py"] } } }

Best practices

Write clear tool names and descriptions, the model reads them.
Validate inputs and return helpful errors.
Never print to stdout in stdio servers, it breaks the protocol. Log to stderr.
